Case study · Workflow design

A five-step pipeline that reads the week of AI news so I don't have to read six mediocre blog posts to find two real facts

Gather → Synthesize → Draft → Review → Format. A fixed, five-step "prompt chaining" workflow, run five times on five real topics — and timed honestly against doing it by hand.

The problem

I wanted a five-minute weekly read that keeps me current for interviews, in a voice already built for the portfolio (clear, curious, practical, analytical, honest, confident, conversational) — so the output is immediately usable, not a generic AI digest. Doing this by hand every week means searching, skimming four to six sources, sorting real facts from filler, drafting, and editing for voice: roughly 35–45 minutes per topic.

The decision: a workflow, not an agent

This is a workflow, specifically the "prompt chaining" pattern — each step's output feeds the next step's input in a fixed sequence I designed before running it even once. The pipeline never chose to skip Synthesize, run Gather twice, or reorder anything; it filled in each step's content, but I owned the path.

That was the right call, not a limitation. The task is well-defined and repeatable every week, so a fixed path with predictable checkpoints — I can inspect the output between any two steps — was worth more than letting a model decide how to research a topic on its own. An agent here would add cost and unpredictability for a task that doesn't need either.

STEP 1
Gather
Search real sources. Source, date, 1–2 sentence factual summary. No opinions yet.
→
STEP 2
Synthesize
Extract 2–4 distinct claims. Drop anything vague or unsupported.
→
STEP 3
Draft
Write 3–5 sentences in the voice card. Lead with what matters most.
→
STEP 4
Review
Check every sentence traces to a claim, isn't generic, matches voice.
→
STEP 5
Format
Labeled markdown block: topic, date, brief, why it matters to me.

Evidence: a real run

Five runs, five topics. Here's Run 3 — hybrid search / RAG — directly relevant to my capstone work, shown as it actually came out of Step 5:

Topic: Hybrid search / RAG · Date: Aug 5, 2026

Hybrid retrieval — combining dense and keyword search — is now measured, not just argued for: one report cites a 12% relevance boost over dense-only search. The bigger signal: multiple sources describe retrieval, not generation, as the main bottleneck in production RAG, with naive pipelines failing at retrieval roughly 40% of the time. Retrieve-then-rerank has become the default production pattern, exactly the architecture I used in my own capstone.

Why it matters to me: my capstone's hybrid + rerank design isn't a workaround I invented — it's the direction the field is actually moving, which is worth saying explicitly in the case study.

Four more runs — frontier model releases, the AI hiring market, AI startup funding, and AI policy — followed the same five steps. Full transcripts of all five are in the GitHub repo.

Outcome: the honest time math

Manual (estimated)Pipeline (actual, this session)
Per topic ~35–45 min: search, skim 4–6 sources, sort real vs. filler, draft, edit for voice ~6–8 min: one search call, extract claims, draft, self-check against criteria
Setup cost — ~15 min, one time, to write the 5-step instruction set
5 topics total ~3–3.75 hours ~50–55 min total (35–40 min run time + 15 min setup)

Honest net: roughly 2–2.5 hours saved across five topics, most of it from skipping the "read six mediocre SEO blog posts to find the two real facts" phase. Gather and Synthesize are where the pipeline earns its keep — Draft and Format save comparatively little once the facts are already in hand.

Where it breaks — what a human still has to check

  • Source quality is uneven, and the pipeline doesn't filter for it on its own. SEO-farmed listicles restate "2026 trends" language with no sourcing. I have to actively reject those in Gather — it took explicit instruction to prefer named, dated sources, not default behavior.
  • Numbers need spot-checking before they go anywhere public. Figures like a "12% relevance boost" came from aggregator sites, not primary papers — fine for an internal weekly read, not fine to repeat externally without verifying against the source.
  • The "why it matters to me" line is the weakest, least reliable step. It's the most subjective output and the one most likely to feel generic without a personal edit.
  • The pipeline has no memory across runs. Nothing catches if next week repeats the same story — I still have to skim last week's brief myself before running this one again.
